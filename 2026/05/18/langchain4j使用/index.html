langchain4j简单使用

前言

1.1、简介

LangChain4j 是专为 Java/Kotlin 开发者设计的 LLM 应用开发框架，是 Python 生态 LangChain 在 JVM 上的官方对等实现，核心是统一大模型 API、简化RAG/Agent/ 记忆 / 工具调用，让 Java 后端快速接入 AI 能力。

中文官方文档：介绍 | LangChain4j 中文文档

官方代码示例：https://github.com/langchain4j/langchain4j-examples

1.2、核心定位与优势

  • Java 原生：纯 JVM 实现、无 Python 依赖、类型安全、兼容 Spring Boot / Quarkus。

  • 统一模型层：一套接口适配 30+ 大模型（通义千问、文心一言、智谱、GPT、Claude、Gemini、Ollama 本地模型等）。

  • 全链路能力：提示模板、聊天记忆、RAG、函数调用、Agent、结构化输出、流式响应。

  • 企业级友好：可观测、安全、测试 Mock、GraalVM 原生镜像、高并发适配。

1.3、核心模块（8 大能力）

1. 模型 I/O（Model I/O）

  • ChatLanguageModel：同步 / 流式对话
  • EmbeddingModel：文本转向量（BGE、text-embedding-ada-002、通义 Embedding）
  • 输出解析：自动转 POJO / JSON / 枚举 / 列表，支持 JSON Schema 强制格式

2. 聊天记忆（Chat Memory）

  • WindowChatMemory：保留最近 N 轮
  • TokenWindowChatMemory：按 Token 截断
  • SummaryChatMemory：对话摘要（节省上下文）
  • 持久化记忆（Redis/DB)

3. RAG（检索增强生成）

  • 文档加载：PDF/Word/Markdown/URL/S3/Blob
  • 分段：递归字符、Markdown 标题、语义分段
  • 向量存储：Milvus、Chroma、Pinecone、Redis、Elasticsearch、PostgreSQL
  • 检索：相似性、多路召回、重排序（RRF）、查询扩展LangChain4j

4. 工具调用（Function Calling）

  • 注解 @Tool 暴露 Java 方法给 AI
  • 支持并行调用、流式部分结果、自动参数校验、嵌套工具
  • AI 自主判断何时调用、传参、整合结果

5. Agent（智能体）

  • ReAct / Plan-and-Execute
  • 多 Agent 协作、状态持久化、断点恢复
  • 长任务、自动规划、跨工具工作流

6. 提示（Prompt Template）

  • Mustache / StringTemplate 模板
  • 多轮对话、系统提示、动态变量

7. 结构化输出

  • POJO 直接映射：List findOrders(String query)
  • 解析失败自动重试

8. 企业级特性

  • 安全：提示词注入防护、敏感数据脱敏
  • 可观测：耗时、Token、调用链、监控
  • 测试：MockChatLanguageModel 单元测试
  • 性能：向量 SIMD 加速、GraalVM 原生镜像

1.4、目前主流集成清单

✅ 大模型（国内）

  • 通义千问（Qwen）、文心一言（ERNIE）、智谱清言（GLM）、DeepSeek、月之暗面、MiniMax

✅ 向量库

  • Milvus、Chroma、Pinecone、Redis、FAISS、Elasticsearch、PostgreSQL (pgvector)。

✅ 框架集成

  • Spring Boot Starter、Quarkus、Scheduled Tasks

1.5、典型应用场景

  • 智能客服、知识库问答（RAG）
  • 代码助手、文档总结
  • 业务数据自然语言查询（NLQ）
  • 自动化工作流（Agent + 工具调用）
  • 企业内部 AI 助手

1.6、与 Spring AI 简单对比

  • LangChain4j：功能更全（RAG/Agent/ 记忆 / 工具更成熟）、灵活度高、社区活跃、多模型适配广
  • Spring AI：更轻、Spring 原生、配置简洁、适合 Spring 深度集成

带工具的问答


  static class TimeTool{
        @Tool("获取当前时间")
        public static LocalDateTime getTime(){
            return LocalDateTime.now();
        }
    }
     /*
       第1次: 模型识别到需要工具,返回工具调用请求(不是最终答案)
       你执行工具: 在本地执行Java方法获取真实数据
       第2次: 模型拿到工具返回的数据,生成人类可读的最终答案
       */
    private static void testTool() {
        //使用系统工具
        ZhipuAiChatModel zhipuAiChatModel = ZhipuAiChatModel.builder()
                .apiKey(ChatModelConfig.ZHIPU_API_KEY)
                .model(AiModelTypeEnum.GLM_4_5_AIR.getModelName())
                .build();

        List<ChatMessage> messages = new ArrayList<>();
        messages.add(UserMessage.from("当前时间是多少"));
        ChatRequest request = ChatRequest.builder()
                .messages(messages)
                .toolSpecifications(ToolSpecifications.toolSpecificationsFrom(TimeTool.class))
                .build();

        ChatResponse chatResponse = zhipuAiChatModel.chat(request);
        AiMessage aiMessage = chatResponse.aiMessage();
        while (aiMessage.hasToolExecutionRequests()) {
            System.out.println("Model requested tool execution:");

            // 添加模型消息到消息列表
            messages.add(aiMessage);

            for (ToolExecutionRequest toolRequest : aiMessage.toolExecutionRequests()) {
                System.out.println("  Tool: " + toolRequest.name());
                System.out.println("  Arguments: " + toolRequest.arguments());
                String result;
                if ("getTime".equals(toolRequest.name())) {
                    LocalDateTime time = TimeTool.getTime();
                    result = time.format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
                } else {
                    result = "Unknown tool";
                }
                ToolExecutionResultMessage resultMessage = ToolExecutionResultMessage.from(
                        toolRequest,
                        result
                );
                // 添加工具执行结果到消息列表
                messages.add(resultMessage);
                chatResponse = zhipuAiChatModel.chat(request);
                aiMessage = chatResponse.aiMessage();
            }
        }

        System.out.println("Final response: " + aiMessage.text());
    }

AI 服务

上面的代码涉及ChatModel、ChatMessage 和 ChatMemory等是较为底层的api，灵活但是需要手动构建，写大量重复性代码。于是LangChain4j 目前提供了两个高级概念：AI 服务 和 链（Chains）。

链 (Chains) (传统)

链的概念源于 Python 的 LangChain（在 LCEL 引入之前）。

其核心思想是为每个常见用例，如聊天机器人或 RAG，提供一个链。链将多个底层组件结合起来，并协调它们之间的交互。它们的主要问题是，如果你需要自定义某些东西，它们会显得过于死板。目前，LangChain4j 仅实现了两种链：ConversationalChain 和ConversationalRetrievalChain，并且暂时没有计划增加更多。

一种专为 Java 设计的解决方案，称为 AI 服务。其思想是将与 LLM 和其他组件交互的复杂性隐藏在一个简单的 API 后面。这种方法与 Spring Data JPA 或 Retrofit 非常相似：你声明性地定义一个具有所需 API 的接口，然后 LangChain4j 提供一个实现此接口的对象（代理）。

你可以将 AI 服务看作应用程序中服务层的一个组件。它提供 AI 服务。

AI 服务处理最常见的操作：

  • 为 LLM 格式化输入
  • 解析 LLM 的输出

它们还支持更高级的功能：

  • 聊天记忆
  • 工具
  • RAG

AI 服务可用于构建有状态的聊天机器人，以促进来回交互，也可用于自动化流程，其中每次对 LLM 的调用都是独立的。

简单代码示例：

定义一个ai服务的接口：

public interface MyAiService {

    String getAnswer(String question);
}

使用：

   public static void main(String[] args) {
        ChatModel model = QwenChatModel.builder()
                .apiKey(ChatModelConfig.ALI_API_KEY)
                .modelName("qwen-max")
                .build();
        ChatMemory chatMemory = MessageWindowChatMemory.withMaxMessages(10);
        // 创建AI服务
        MyAiService aiService = AiServices.builder(MyAiService.class)
                .chatModel(model)
                .chatMemory(chatMemory)
                .build();

        String answer = aiService.getAnswer("who are you");
        System.out.println(answer);
        String answer2 = aiService.getAnswer("who am I");
        System.out.println(answer2);
        String answer3 = aiService.getAnswer("I am bcym");
        System.out.println(answer3);
        String answer4 = aiService.getAnswer("who am I");
        System.out.println(answer4);
    }

Agentic 系统

Agentic 系统架构 可以分为两大类：

  1. 工作流（workflows）
  2. 纯代理（pure agents）

在 LangChain4j 中，Agent 是使用 LLM 执行某个特定任务（或一组任务）的组件。

   public static void main(String[] args) {
        ChatModel model = QwenChatModel.builder()
                .apiKey(ChatModelConfig.ALI_API_KEY)
                .modelName("qwen-max")
                .build();
        ChatMemory chatMemory = MessageWindowChatMemory.withMaxMessages(10);
        // 创建AI服务
        MyAiService aiService = AiServices.builder(MyAiService.class)
                .chatModel(model)
                .chatMemory(chatMemory)
                .build();

        String answer = aiService.getAnswer("who are you");
        System.out.println(answer);
        String answer2 = aiService.getAnswer("who am I");
        System.out.println(answer2);
        String answer3 = aiService.getAnswer("I am bcym");
        System.out.println(answer3);
        String answer4 = aiService.getAnswer("who am I");
        System.out.println(answer4);
    }

最佳实践是：在 @Agent 注解中提供简短的描述，尤其在 纯代理模式 下，其他 Agent 需要了解该 Agent 的能力，以便决定何时调用。

可以使用 AgenticServices.agentBuilder() 方法来创建该 Agent 的实例，并指定接口与 Chat 模型:

CreativeWriter creativeWriter = AgenticServices
        .agentBuilder(CreativeWriter.class)
        .chatModel(myChatModel)
        .outputKey("story")
        .build();

从本质上讲，Agent 与普通 AI 服务功能相同，只是它们可以被组合到更复杂的工作流和 Agentic 系统中。

主要区别在于：

Agent 需要指定 outputKey—— 即结果会存储在共享变量中，以便其他 Agent 使用。

也可以直接在注解中声明，而不是在代码中设置，例如：

@Agent(outputName = "story", description = "Generates a story based on the given topic")

测试代码：

  /**
     * 顺序工作流型的 Agentic 系统
     * 常见的一种方式是将多个 Agent 串联起来，一个接一个地执行。
     * 这可以通过 顺序工作流模式 实现：一个 Agent 的输出作为下一个 Agent 的输入。
     */
    private static void testSequentialAgenticService(){
        ZhipuAiChatModel zhipuAiChatModel = ZhipuAiChatModel.builder()
                .apiKey(ChatModelConfig.ZHIPU_API_KEY)
                .model(AiModelTypeEnum.GLM_4_5_AIR.getModelName())
                .build();
        //或者加在注解中@Agent(outputKey = "story", description = "Generates a story based on the given topic")
        CreativeWriter creativeWriter = AgenticServices
                .agentBuilder(CreativeWriter.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("story")
                .build();

        AudienceEditor audienceEditor = AgenticServices
                .agentBuilder(AudienceEditor.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("story")
                .build();

        StyleEditor styleEditor = AgenticServices
                .agentBuilder(StyleEditor.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("story")
                .build();

        // 顺序工作流型的 Agentic 系统
        UntypedAgent novelCreator = AgenticServices
                .sequenceBuilder()
                .subAgents(creativeWriter, audienceEditor, styleEditor)
                .outputKey("story")
                .build();
        Map<String, Object> input = Map.of(
                "topic", "爱情动作片",
                "style", "血脉喷张",
                "audience", "年轻人"
        );

        String story = (String) novelCreator.invoke(input);
        System.out.println(story);
    }

    /**
     * 循环工作流型的 Agentic 系统
     * 常见的一种方式是利用 LLM 反复改进文本（例如故事），直到达到满意效果。
     * 这可以通过 循环工作流模式 实现：一个 Agent 多次执行，直到满足退出条件。
     */
    private static void testLoopAgenticService(){
        ZhipuAiChatModel zhipuAiChatModel = ZhipuAiChatModel.builder()
                .apiKey(ChatModelConfig.ZHIPU_API_KEY)
                .model(AiModelTypeEnum.GLM_4_5_AIR.getModelName())
                .logResponses(true)
                .build();
        StyleEditor styleEditor = AgenticServices
                .agentBuilder(StyleEditor.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("story")
                .build();

        StyleScorer styleScorer = AgenticServices
                .agentBuilder(StyleScorer.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("score")
                .build();
        UntypedAgent styleReviewLoop = AgenticServices
                .loopBuilder()
                .subAgents(styleScorer, styleEditor)
                .maxIterations(5)
                .exitCondition(agenticScope -> agenticScope.readState("score", 0.0) >= 0.8)
                .build();
        CreativeWriter creativeWriter = AgenticServices
                .agentBuilder(CreativeWriter.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("story")
                .build();

        StyledWriter styledWriter = AgenticServices
                .sequenceBuilder(StyledWriter.class)
                .subAgents(creativeWriter, styleReviewLoop)
                .outputKey("story")
                .build();

        String story = styledWriter.writeStoryWithStyle("恐怖片", "紧张刺激");
        System.out.println(story);
    }

    /**
     * 多个 Agent 可以 独立处理相同输入，这时可用 并行工作流模式。
     */
    private static void testParallelAgenticService(){
        ZhipuAiChatModel zhipuAiChatModel = ZhipuAiChatModel.builder()
                .apiKey(ChatModelConfig.ZHIPU_API_KEY)
                .model(AiModelTypeEnum.GLM_4_5_AIR.getModelName())
                .logResponses(true)
                .build();
        DinnerPlan dinnerPlan = AgenticServices
                .agentBuilder(DinnerPlan.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("dinner")
                .build();

        MoviePlan moviePlan = AgenticServices
                .agentBuilder(MoviePlan.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("movie")
                .build();

        ActivityPlan activityPlan = AgenticServices
                .agentBuilder(ActivityPlan.class)
                .chatModel(zhipuAiChatModel)
                .tools(new Activity())
                .outputKey("act")
                .build();

        EveningPlannerAgent parallelAgents = AgenticServices
                .parallelBuilder(EveningPlannerAgent.class)
                .subAgents(dinnerPlan, moviePlan, activityPlan)
                .outputKey("plans")
                .output(agenticScope -> {
                    List<String> dinner = agenticScope.readState("dinner", List.of());
                    List<String> movie = agenticScope.readState("movie", List.of());
                    List<String> act = agenticScope.readState("act", List.of());
                    System.out.println("Dinner: " + dinner.size() + ", Movie: " + movie.size() + ", MakeLove: " + act.size());
                    List<EveningPlan> plans = new ArrayList<>();
                    for (int i = 0; i < movie.size(); i++) {
                        if (i >= dinner.size()) break;
                        plans.add(new EveningPlan(dinner.get(i), movie.get(i),act.get(i)));
                    }
                    return plans;
                })
                .build();
        List<EveningPlan> planList = parallelAgents.plan("激动");
        for (EveningPlan plan : planList) {
            System.out.println(plan.getDinner() + " -> " + plan.getMovie() + " -> " + plan.getAct());
        }

    }

                .outputKey("response")
                .build();

        UrologyExpert urologyExpert = AgenticServices.agentBuilder(UrologyExpert.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("response")
                .build();
        NeurologyExpert neurologyExpert = AgenticServices.agentBuilder(NeurologyExpert.class)
                .chatModel(zhipuAiChatModel)
                .outputKey("response")
                .build();


        UntypedAgent expertsAgent = AgenticServices.conditionalBuilder()
                .subAgents(agenticScope -> agenticScope.readState("category", MedicalDeptEnum.UNKNOWN) == MedicalDeptEnum.DENTISTRY, dentistryExpert)
                .subAgents(agenticScope -> agenticScope.readState("category", MedicalDeptEnum.UNKNOWN) == MedicalDeptEnum.OPHTHALMOLOGY, ophthalmologyExpert)
                .subAgents(agenticScope -> agenticScope.readState("category", MedicalDeptEnum.UNKNOWN) == MedicalDeptEnum.SURGERY, surgeryExpert)
                .subAgents(agenticScope -> agenticScope.readState("category", MedicalDeptEnum.UNKNOWN) == MedicalDeptEnum.UROLOGY, urologyExpert)
                .subAgents(agenticScope -> agenticScope.readState("category", MedicalDeptEnum.UNKNOWN) == MedicalDeptEnum.NEUROLOGY, neurologyExpert)
                .build();

        ExpertRouterAgent expertRouterAgent = AgenticServices
                .sequenceBuilder(ExpertRouterAgent.class)
                .subAgents(category, expertsAgent)
                .outputKey("response")
                .build();
        String response = expertRouterAgent.ask("空调吹多了，我头疼怎么办");
        System.out.println(response);
    }

  • 向量存储 Bean
  • 对话记忆 Bean
  • 只需要 @Resource 或 @Autowired 注入即可

作用：

注意：LangChain4j 从 0.21+ / 1.0+ 开始重构 HTTP 层，引入了 HttpClient SPI 机制LangChain4j：

类路径下同时存在 JdkHttpClient（langchain4j-http-client-jdk）和 SpringRestClient（langchain4j-http-client-spring-restclient）

Spring Boot 环境下，两个客户端都会被自动加载，导致冲突

官方明确要求：必须显式指定一个客户端。

解决方法：直接排除http实现

 <!-- Spring Boot Starter -->
        <dependency>
            <groupId>dev.langchain4j</groupId>
            <artifactId>langchain4j-spring-boot-starter</artifactId>
            <version>${langchain4j.version}-beta24</version>
            <!-- 关键：排除冲突HTTP客户端 -->
            <exclusions>
                <exclusion>
                    <groupId>dev.langchain4j</groupId>
                    <artifactId>langchain4j-http-client-spring-restclient</artifactId>
                </exclusion>
            </exclusions>
        </dependency>

也可以执行http端，但是我目前的starter中没找到这个配置，可能是langchain4j当前社区非常活跃，依赖更新频繁导致管理混乱，期待后续解决方法。
